# **RF15 \- Padronizar as mensagens entre coletores e coordenador**  
O sistema deve trocar mensagens entre os coletores e o coordenador em formato e tópicos padronizados, com nível de entrega (QoS) definido para cada tipo de mensagem.

Caso de Uso \- Padronizar as mensagens entre coletores e coordenador

| Campo | Descrição |
| :---- | :---- |
| Identificador | UC15 |
| Nome | Padronizar as mensagens entre coletores e coordenador |
| Ator principal | Coletor BLE e Coordenador |
| Pré-condição | Coletor ou coordenador conectado ao *broker* |
| Pós-condição | Mensagens publicadas e interpretadas no formato padronizado |

**História de usuário:**  
Como coletor BLE ou coordenador, quero que todas as mensagens sigam o mesmo formato, para que qualquer participante consiga interpretá-las corretamente, mesmo após atualizações do sistema.

**Critérios de aceitação:**

* O conteúdo das mensagens deve ser JSON, com os campos `versao` (versão do formato), `tipo` (tipo da mensagem), `origem` (identificador de quem publicou: coletor ou coordenador), `timestamp` (UTC, ISO 8601) e `conteudo`.  
* Os tópicos devem seguir uma hierarquia única e documentada:  

| Tópico | Quem publica | Conteúdo | QoS | Retida |
| :---- | :---- | :---- | :---- | :---- |
| coletores/{coletor}/presenca | Coletor | Presença (RF12) | 1 | Sim |
| coletores/{coletor}/sinal-de-vida | Coletor | Sinal de vida (RF12) | 0 | Não |
| coletores/{coletor}/pulseiras/{endereco} | Coletor | Estado e RSSI e, na varredura, quantidade de amostras (RF09, RF18) | 0 | Não |
| pulseiras/{endereco}/liberacao | Coletor | Liberação da posse (RF14) | 1 | Não |
| pulseiras/{endereco}/frequencia-cardiaca | Coletor ativo | Leituras de frequência cardíaca (RF17) | 0 | Não |
| pulseiras/{endereco}/posse | Coordenador | Coletor responsável ou posse liberada (RF14) | 1 | Sim |
| pulseiras/{endereco}/handoff | Coordenador | Comando de *handoff* para a origem liberar a pulseira (RF06) | 1 | Não |
| coordenador/presenca | Coordenador | Presença (RF19) | 1 | Sim |
| coordenador/sinal-de-vida | Coordenador | Sinal de vida (RF19) | 0 | Não |

* A coluna "Quem publica" é uma convenção: o *broker* não impede que outro cliente publique nesses tópicos.  
* QoS 1 (entrega garantida, ao menos uma vez) para mensagens de controle; QoS 0 para estado/RSSI, frequência cardíaca e sinal de vida, em que a perda de uma mensagem é compensada pela seguinte.
* O campo `conteudo` de cada tipo de mensagem deve seguir o formato abaixo:

| Tipo (`tipo`) | Tópico | Campos de `conteudo` |
| :---- | :---- | :---- |
| presenca | coletores/{coletor}/presenca, coordenador/presenca | `estado` (online ou offline); `pulseira` (endereço atendido ou null, só no coletor) |
| sinal-de-vida | coletores/{coletor}/sinal-de-vida, coordenador/sinal-de-vida | sem campos |
| estado-pulseira | coletores/{coletor}/pulseiras/{endereco} | `pulseira` (endereço); `estado` (conectado, desconectado ou nao-encontrado); `rssi` (dBm, ou null se indisponível); `amostras` (inteiro, só na varredura) |
| liberacao-posse | pulseiras/{endereco}/liberacao | `pulseira`; `handoff` (id do comando, quando a liberação responde a um *handoff*) |
| frequencia-cardiaca | pulseiras/{endereco}/frequencia-cardiaca | `pulseira`; `coletor`; `bpm` (inteiro); `rr` (lista de intervalos em ms, quando houver) |
| posse | pulseiras/{endereco}/posse | `pulseira`; `coletor` (identificador do responsável, ou null quando liberada) |
| handoff | pulseiras/{endereco}/handoff | `id` (identificador do *handoff*); `pulseira`; `origem` (coletor que deve liberar) |

* Os termos usados nos campos e valores devem seguir a linguagem ubíqua (ex.: estados conectado, desconectado, conexao-fraca, nao-encontrado).  
* A versão do formato deve mudar sempre que a estrutura de uma mensagem mudar. Mensagens com versão diferente da esperada devem ser descartadas e registradas em *log*.
